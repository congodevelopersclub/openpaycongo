# Approved operator pattern integration

The approval authority comes from [PR225](https://github.com/congodevelopersclub/openpaycongo/pull/225), source revision `045bbbcd0d158b20448bfe6727bb33273fc18500`. This branch selectively reuses its proposal and release records, tenant-scoped MFA review and release services, Filament review surface, and authenticated `/mobile/operator-sms/pattern-releases` endpoint. It does not merge the branch wholesale or enable its Gemma inference and raw-SMS submission pipeline. Synthetic templates enter the same pending-proposal and explicit approval boundary through an operator action.

The canonical signed payload remains the flat eight-field object with `schema_version: "1"`. Its Ed25519 transcript retains PR225's LP16 domain and field order. The parser signing authority remains `OPENPAY_OPERATOR_SMS_PATTERN_SIGNING_SECRET`; the pairing enrollment signer cannot approve a parser release. Android verifies against the separately compiled `OPENPAY_OPERATOR_PATTERN_SIGNING_PUBLIC_KEY`. An import wrapper cannot establish or replace that authority. A missing public-key pin refuses imports.

The wallet parser requires `{amount}`, `{currency}`, `{reference}`, `{customer}`, and `{occurred_at}` once each in a bounded literal template. The last two fields extend the template capability without changing the signed object or signature transcript. Older three-field patterns do not contain enough evidence for this wallet workflow and remain review-only here. Older PR225 clients reject the extended template; they must not infer customer identity or provider time from missing fields. Reapproval and a new signed release are required for a different template.

The endpoint's `release_id` remains its existing opaque database UUID. The deposit's `parser_release_id` is a SHA-256 digest of the canonical signed transcript, indexed on that same approved release record. These identifiers have different purposes and must not be substituted for one another. Existing canonical records receive the digest through the migration; publication records the digest atomically with the immutable release. SMS ingestion resolves it within the enrolled installation's organization and checks the approved proposal, provider, sender, version, and capture validity window.

The earlier schema-2 bundle, pairing-key publisher, and separate parser registry were draft-only work and are removed. They were never on `main` and have no supported authority upgrade. If a disposable environment ran that draft, discard its imported parser rules and explicitly approve and import a canonical release. Never copy its claimed approval timestamp into an approved proposal or backdate a new release.

Captures before approval or after expiry remain in the encrypted inbox for review. An already staged request with a valid original capture timestamp may retry after expiry without changing its financial payload or first evidence. A conflicting duplicate stays reviewable while unrelated SMS continue processing. Parser approval authenticates the rule and its review provenance, not provider settlement or execution by an uncompromised phone.

Verification belongs to the Docker CI gates and the synthetic acceptance walkthrough. Automated coverage checks the signature format, configured authority, approval windows, immutable retry evidence, tenant authorization, ledger idempotency, and signed HTTP delivery. Physical installation and SMS receipt require the separate device acceptance record.
