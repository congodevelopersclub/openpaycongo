# Payment request credit allocation

Payment requests are customer-scoped. They intentionally contain no organization or installation identifier, and each balance is keyed only by `(customer_id, currency)`. An application must not treat its own organization identifier as a customer-credit account.

Creation locks that balance. A sufficient balance charges the request atomically; otherwise the request is stored as `pending`. The policy is deliberately all-or-nothing: a short balance is not partially consumed, and a smaller later request cannot bypass an older shortfall. Set `PAYMENT_REQUEST_PENDING_EXPIRY_DAYS` to a value no lower than 30 days; the conservative default is 90.

A committed provider-credit deposit emits an after-commit event. Its database-queue listener posts the credit once, expires overdue requests, and allocates the remaining unexpired requests by `created_at`, then UUID. Allocation events are recorded in a durable delivery row inside the allocation transaction and dispatched from the database queue after commit. Delivery is at-least-once: callback consumers must be idempotent using `paymentRequestId` as their allocation key, because a process can fail after a successful handoff but before the delivery row is marked dispatched. The recovery command may therefore re-enqueue the same allocation safely. Currency balances never mix. Late deposits leave expired requests expired and available credit unallocated.

Payment-request idempotency HMAC rotation is two-phase: every node first receives the complete old-and-new read ring, then every node switches its active write key. A key ID is permanently bound to its secret and must never be rebound. Requests are retained indefinitely, so historical keys must remain configured for the lifetime of every row that references their purpose-separated secret fingerprint. Creation fails closed for a customer when a persisted fingerprint is missing from the ring, including secret drift under the same key ID; removing a key requires an explicit retention and purge migration first.
